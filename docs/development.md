## 必须保留的约束

1. 所有数据操作包含 namespace/user/agent scope；模型无法决定 scope、来源 ID 或数据库操作。
2. 推荐 `/v1/events` 先事务提交事件与任务，模型在独立 worker 中执行；兼容 `/v1/ingest` 先模型后原子提交。同事件 ID 不得静默换负载或切换路径；删除后留墓碑，禁止原事件重放恢复内容。worker 在提交结果时复查租约与来源，不宣称外部 API exactly-once。
3. `fact_key` 仅用于显式语义槽位。替代时保留历史并使旧派生摘要失效；不声称能解决所有自然语言矛盾。
4. 原始对话用于审计；模型提取与对话巩固只将 user 消息当作事实候选，不能把 assistant 的猜测直接当作用户事实。角色区间与摘要校验用于确保内部结构一致，不是身份签名，业务后端仍负责真实消息角色。巩固保留实际使用的来源和生成方法；重复事实不会引入来源循环。
5. 召回不修改访问次数，只有显式 rehearse 才强化。归档使用快照版本检查，避免覆盖并发强化；模型巩固在提交事务时复查来源是否仍有效。
6. 模型输出校验完成状态、结构、数值和长度，异常响应不能部分落库。模型错误不向客户端泄露 provider body 或凭证。
7. 上下文预算是字符数。只放入完整 JSON 记忆条目，超预算整条省略，included_ids 与实际上下文一致。

## 排序与遗忘

英文/Unicode 单词与中文相邻双字片段用于 FTS5 候选搜索和最终 BM25；中英文紧邻时仍分开匹配。词法相关度为 `BM25 / (1 + BM25)`。向量将余弦超过配置阈值的部分映射到 0～1，再与词法组合；远程后端默认 0.35，本地模型使用独立阈值。阈值随模型和业务数据变化，不能把小型合成诊断当作通用标定，详见 [评测记录](evaluation.md)。

基础半衰期：working 1 小时、episodic 14 天、semantic 90 天、procedural 180 天。实际半衰期乘以 `(0.5 + importance) × (1 + 0.5 × log(1 + access_count))`；最近一次显式复习或创建时间作为衰减起点。保留强度为 `2 ** (-elapsed_days / half_life)`。pinned 保留强度为 1，但不会越过 TTL。

相关度对重要性、保留强度、近期性的加权结果起门控作用，零相关条目不会被重要性抬进结果。衰减不会自行删除记录；显式维护默认预览归档候选。所有数值都是可解释工程启发式，不是认知科学实验结论。

## 存储和演进

SQLite 使用 WAL、外键、busy timeout、进程内锁与 `BEGIN IMMEDIATE`。部分唯一索引限制同 scope 的 active 内容指纹和 fact key。`PRAGMA user_version=2` 标记核心 schema，v1 来源/FTS5 回填迁移受事务保护；未知版本拒绝打开。队列独立 schema 标记为 1。升级前备份，回滚程序时同时恢复匹配版本数据库。

兼容 ingest 的 events 保存原始响应快照；可靠事件回执从当前 episode 和 job 读取状态。删除相关记忆会清空旧事件快照并留 hash 墓碑。历史备份和 WAL 的安全擦除属于部署数据策略。sources 完整关系不能由 JSON 中的 100 条预览反向覆盖；删除、失效传播和循环校验必须检查完整关系。

远程向量按提供商地址和模型名缓存，本地 key 还包括模型 commit、FastEmbed 版本及分段约定。模型替换必须换模型名；同名变维度或缓存损坏明确降级，可显式 rebuild。索引构建在查询路径之外，每批最多 32 条和 32000 字符。未覆盖全部记录时允许已索引语义候选参与，但必须标为 hybrid_partial 并报告覆盖率。等待编码后重新读取候选状态；写缓存事务再检查 active/TTL，避免删除或归档竞态。

## 后续开发顺序

1. v0.3 已增加冻结的 25 题时间线、8 题真实最终回答子集和 8 张合成图片。下一步扩展独立真实图片/任务数据，保留现有标签和失败案例，分开报告检索、最终回答与费用。`requires_review` 和 confidence 都不保证真实性。
2. 本地增量 worker 已补齐新记忆接入。下一步按真实库规模/并发/p95 决定 ANN 或 PostgreSQL；当前精确扫描万条约 1 秒，不能靠 top-k 掩盖全扫描成本。本阶段不扩张数据库架构，仍保留 scope/TTL/来源/幂等和词法降级契约。
3. 如果业务需要，增加用户身份授权层、配额、审计、数据保留策略和部署监控。namespace key 不能替代用户身份。
4. 根据实际 agent 集成需要增加 MCP adapter、异步客户端或框架插件；当前 REST/OpenAPI 已是可接入边界，不必先引入完整框架。
5. 只有在多跳实体查询确有收益时再考虑图后端；参照调研固定上游提交并重新核查许可。
