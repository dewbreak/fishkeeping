## 必须保留的约束

1. 所有数据操作包含 namespace/user/agent scope；模型无法决定 scope、来源 ID 或数据库操作。
2. 摄入在网络调用和结果校验成功后才开始事务，事件与候选一并提交。同事件 ID 不得静默换负载；删除后留墓碑，禁止原事件重放恢复内容。
3. `fact_key` 仅用于显式语义槽位。替代时保留历史并使旧派生摘要失效；不声称能解决所有自然语言矛盾。
4. 原始对话用于审计；模型提取只将 user 消息当作事实候选，不能把 assistant 的猜测直接当作用户事实。巩固保留全部来源和生成方法。
5. 召回不修改访问次数，只有显式 rehearse 才强化。归档使用快照版本检查，避免覆盖并发强化；模型巩固在提交事务时复查来源是否仍有效。
6. 模型输出校验完成状态、结构、数值和长度，异常响应不能部分落库。模型错误不向客户端泄露 provider body 或凭证。
7. 上下文预算是字符数。只放入完整 JSON 记忆条目，超预算整条省略，included_ids 与实际上下文一致。

## 排序与遗忘

英文/Unicode 单词与中文相邻双字片段用于 BM25；中英文紧邻时仍分开匹配。词法相关度为 `BM25 / (1 + BM25)`。可选向量以余弦 0.35 作为启发式阈值，将阈值以上部分映射到 0～1，再与词法组合。阈值未经过真实任务校准，应使用固定评测集验证。

基础半衰期：working 1 小时、episodic 14 天、semantic 90 天、procedural 180 天。实际半衰期乘以 `(0.5 + importance) × (1 + 0.5 × log(1 + access_count))`；最近一次显式复习或创建时间作为衰减起点。保留强度为 `2 ** (-elapsed_days / half_life)`。pinned 保留强度为 1，但不会越过 TTL。

相关度对重要性、保留强度、近期性的加权结果起门控作用，零相关条目不会被重要性抬进结果。衰减不会自行删除记录；显式维护默认预览归档候选。所有数值都是可解释工程启发式，不是认知科学实验结论。

## 存储和演进

SQLite 使用 WAL、外键、busy timeout、进程内锁与 `BEGIN IMMEDIATE`。部分唯一索引限制同 scope 的 active 内容指纹和 fact key。`PRAGMA user_version=1` 标记 schema；未知版本拒绝打开，后续改表必须提供显式迁移与回滚验证，不直接升版本号掩盖不兼容。

events 保存原始响应快照以保证重放稳定；因此旧事件重放可能显示当初的状态，当前状态应重新 GET。删除相关记忆会清空该事件快照并留 hash 墓碑。历史备份和 WAL 的安全擦除属于部署数据策略。

向量按提供商地址和模型名缓存。模型替换必须换模型名；同名却变维度会明确降级。每次召回的新增向量量受限，未完成所有候选缓存时整体使用词法，避免把不完整向量检索伪装成完整结果。等待网络后重新读取候选状态，剔除期间被删除、替代或归档的记录。

## 后续开发顺序

1. 用真实 DeepSeek 凭证运行示例，并建立包含偏好变化、矛盾、中文同义表达、错误提取的固定质量集。分别测量召回、最终回答、成本与延迟。
2. 建立独立向量索引/预热任务；扩大数据量前评估 PostgreSQL + 向量后端，保留现有 scope、来源和幂等契约。
3. 如果业务需要，增加用户身份授权层、配额、审计、数据保留策略和部署监控。namespace key 不能替代用户身份。
4. 根据实际 agent 集成需要增加 MCP adapter、异步客户端或框架插件；当前 REST/OpenAPI 已是可接入边界，不必先引入完整框架。
5. 只有在多跳实体查询确有收益时再考虑图后端；参照调研固定上游提交并重新核查许可。

未实现的事项：自主后台调度、完整知识图谱、生产集群、模型权重学习、自动确认任意矛盾、多模态记忆和正式召回 benchmark。
