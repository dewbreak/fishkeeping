# 真实照片、复杂表格与短视频诊断

2026-10-28，v0.4。六道冻结题使用两张有许可的真实照片、USDA 同一报告的两页复杂统计表，以及同一段 32 秒动画的两个时间窗。它们覆盖空间关系、边缘裁切、多层表头、上下两表、单位/脚注、重复切镜与动作顺序；不是拥挤实拍场景、长视频或通用准确率 benchmark。

[素材/题目清单](../tests/fixtures/real_media_cases.json)在模型测试前目视核验并冻结。canonical SHA256 为 `255a9affb46eed171c6414da3aa4cb746cf8c9182a1a06590ea272bb6caf7446`。来源与许可、GitHub 固定提交及方案取舍见 [调研](research/video-and-real-media.md)。未使用业务数据，未提交媒体文件、模型权重或凭证。动画署名：`(c) copyright 2008, Blender Foundation / www.bigbuckbunny.org`，CC-BY-3.0。

## 方案与费用

照片比较 `detail=original` 与 `low`；表格比较 PDF 渲染页的 original 输入与本地 OCR 的完整证据组。下文“原图”指 original detail，视频的 original 则指解码后的 JPEG 帧，不是原始视频字节。空 OCR 组回退到同一原图请求，直接复用已有答案，不再次付费。稻米 OCR 与全部视频都有 `requires_review=true`，本次实验明确使用 `allow_review=True`；生产默认适配器会阻止这些请求。

视频比较全片均匀 12 帧/original 与问题明确时间窗内自适应 6 帧/low。它同时改变范围、帧数和图片 detail，是组合策略比较，不能将收益全部归因于自适应算法。`start_seconds/end_seconds` 来自题目；细粒度 `evidence_intervals` 和参考答案只用于事后评分，未输入选择器或模型。输入模型的是时间戳与真实选中 JPEG，不是接触表或字幕转写。

独立持久账本上限为 **12 次、US$0.05、单次最多 1024 输出 tokens**。12 个方案去重后 11 个请求，保守预留 **US$0.0335865**。实际 11 次均返回 HTTP 200，10 个输出通过适配器，最后一个因 `invalid_output` 被拒绝，没有重试。共 **15,888 输入 + 1,216 输出 = 17,104 tokens**，按核查当日峰值未缓存价估算 **US$0.0062256**，不是账户扣费账单。失败输出的 usage 仍计费；复用结果不重复计费。

[实际调用/账本](validation/media-live-2026-10-28.json)保留失败状态，不能因 HTTP 200 改写为全成功。[逐项人工审查](validation/media-manual-review-2026-10-28.json)分开记录内容、引用和适当的不确定性；关键词命中仅为辅助诊断。原始模型文本只保留在忽略目录，审查报告保存回答哈希、错误字段与理由。

## 真实结果与失败

| 案例 | 原图/全片输入 tokens | 优化输入 tokens | 输入变化 | 人工内容核验 |
| --- | ---: | ---: | ---: | --- |
| 咖啡照片：数量与相对位置 | 361 | 361 | 0% | 两侧均完整 |
| 火箭照片：裁切塔架计数与起飞不确定性 | 364 | 364 | 0% | 两侧均完整；优化的 uncertain=true 合理 |
| 玉米多层表头 | 1178 | 1178（复用） | 0% | 数字/年份/单位/脚注正确，但缺引用 ID |
| 稻米上下两表 | 1175 | 2063 | **增加 75.6%** | 两侧均把九月单产错配成十月值 |
| 动画 13–17 秒重复切镜 | 3553 | 1454 | **减少 59.1%** | 基线缺少完整顺序；优化的三只→白兔→三只→白兔有帧支持 |
| 动画 19–23 秒动作与特写 | 3557 | 1458 | **减少 59.0%** | 基线合理弃答但未完成任务；优化输出校验失败，无法审查 |

照片原本尺寸较小，本轮 `low` 没有降低服务端输入 token；不能假定每张图都能节省。玉米 OCR 检测 290 区域，超出 256 区域保留上限，完整证据组在 10,000 字符内也放不下，所以返回空组并要求复核。本次原图回答正确，不能据此宣称 OCR 识别成功。

稻米 OCR 保留全部 104 区域，包含正确的 `8,800`（九月）和 `8,650`（十月），模型却将九月也回答为 8,650。这是列关联错误，单纯字符 OCR 正确不能解决；六个数字中五个正确也不能把整题判通过。答案保留 `1,000 cwt`，这里的美国 cwt 为 100 磅，中文不宜只写易歧义的英担。完整 OCR 还比原图多用 tokens，因此复杂表格不默认强推 OCR 省费，应先看复核标记、证据规模和结构，再显式选区域或原图；本轮没有追加付费 ROI 试验。

所有存储的 11 个方案结果中 7 个内容完整，其中玉米优化结果只是复用；独立有效回答为 10 个，另有 1 次输出失败。这个样本量、同源视频和重复方案不适合汇总成泛化准确率。引用缺失、表格错误、视频弃答和校验失败均保留，不删题、不改参考答案。

## 采样消融与覆盖口径

[离线采样消融](validation/video-sampling-ablation-2026-10-28.json)只解码一次、复用同一真实候选帧，未调用模型。两题按原始浮点 PTS 落入冻结窄区间的命中数如下：

| 同条件采样 | 13–17 秒题 | 19–23 秒题 |
| --- | ---: | ---: |
| 指定窗口 uniform6 | 3/4 | 4/4 |
| 指定窗口 adaptive6 | 3/4 | 3/4 |
| 全片 uniform6 | 0/4 | 1/4 |
| 全片 adaptive6 | 0/4 | 1/4 |
| 指定窗口 uniform12（只有 10 个候选） | 4/4 | 4/4 |

当前数据不支持 adaptive 优于同窗 uniform。时间窗带来的差异更明显；增加帧数能提高这里的区间命中，同时增加潜在费用。全片 12 帧付费基线两题均为 0/4 窄区间命中，但边界外的 14.8/20.8 秒帧仍可显示相关角色，因此不能称为“没有任何相关证据”。第一题优化的 13.2 秒帧也清楚有三只动物，虽落在冻结 13.3–13.8 区间外，人工语义核验仍接受其证据；没有为结果扩大标签区间。

`requires_review=false` 同样不是内容完整保证：某个 uniform6 条件未触发启发式警告，却只有 3/4 窄区间命中。回答应引用实际帧并表达无法确认，不补出帧间剧情。

## 复验与工程边界

安装 `dev/local/vision` extra；PDF 页面还需本地 Poppler。首次显式下载约 13 MB，随后离线校验源哈希与派生页面 provenance：

```text
python scripts/media_assets.py --download
python scripts/evaluate_media.py --output .tmp/media-v04-offline.json
python scripts/live_media.py
python scripts/ablate_video_sampling.py
python scripts/smoke_media.py
```

`live_media.py` 默认仅预览，无网络/模型调用；`--live` 才付费。保留 `.tmp/media-v04-budget.json`，不清除账本绕过上限；已有请求哈希的未知/失败结果不重试，答案缓存丢失也不重复发送。准备文件、当前 fixture、请求字节顺序、缓存与预留哈希不一致时提前拒绝。旧 v0.3 的八次账本不重置、不扩容。正式 CI 只有离线 mock 测试，不下载素材、不安装权重、不调用付费模型。

受限 Windows 环境应先将进程 `TEMP`/`TMP` 设为可写项目 `.tmp`，示例见 [视频指南](video.md)。首次失败是沙箱默认临时目录不可写，修正后同一 MP4 成功解码；源容器声明 812 帧，实际 811 帧、末 PTS 32.4 秒，处于已记录的一帧容差内，不用 FPS 伪造时间戳。

[离线准备报告](validation/media-offline-2026-10-28.json)的 wall 包含 OCR/解码/打包，parent CPU 不含解码子进程；RSS 是父进程累计峰值，不是单次增量内存。OCR 冷启动和执行顺序不同，不能据此比较算法资源公平性。[真实 HTTP smoke](validation/media-http-smoke-2026-10-28.json)验证缓存素材的 analyze/events/重放/隔离/来源删除，全程零付费。

未验证实拍快速动作、长视频、多路并发、音轨、跨页表格或 GPU VLM。视频事件不保存原片和帧像素，调用方负责按哈希保留审计文件。后续优先独立困难样本、结构化表格模型与同窗同分辨率比较，不以加大付费循环掩盖当前失败。
